2.3 Router: Why Sonnet, Not Opus

The Router performs pattern matching and template assembly, not deep
creative reasoning. Sonnet 4.5 handles classification and prompt
preparation at 90% of Opus quality and 2x the speed. Saving Opus quota
for revenue-generating tasks (proposals, complex emails) is the smart
allocation. Router adds no M365 search — it stays fast and light. Deep
context retrieval happens in the execution project where it’s actually
needed.

3. Context Architecture: In-Context, Not RAG

3.1 Why RAG Won’t Activate

Claude Projects RAG activates automatically when uploaded files approach
the 200,000-token context window limit. Our project files total ~12–15K
tokens. That’s 7% of the limit. RAG will not activate. All files load
directly into every conversation.

3.2 Why In-Context Is Superior for Our Use Case

  ------------------------- ---------------------------------------------
  Factor                    In-Context Advantage

  Retrieval risk            Zero. Claude sees ALL files every time.
                            Nothing can be missed. RAG can fail to
                            retrieve the right chunk.

  Cross-referencing         Claude can compare a cold outreach example
                            with a complaint response simultaneously to
                            calibrate tone. RAG would retrieve only 1–2
                            matches.

  Latency                   No search step. Files are already loaded. RAG
                            adds retrieval overhead.

  Attention quality         Research shows curated, relevant context
                            outperforms comprehensive context. At 12K
                            tokens, all our files are relevant. No
                            dilution.

  Lost-in-the-middle        This effect (30%+ accuracy loss) occurs at
                            20–30+ documents / 100K+ tokens. We have 6–8
                            files at 12K tokens. Not a factor.
  ------------------------- ---------------------------------------------

+-----------------------------------------------------------------------+
| WHEN WOULD WE NEED RAG?                                               |
|                                                                       |
| Only if project files grow past ~150K tokens. This would require      |
| uploading 100+ example emails, full supplier catalogs, entire service |
| databases. Unlikely for a 5-person DMC.                               |
|                                                                       |
| If we ever reach this scale, the Router architecture already supports |
| splitting: create more specialized execution projects (e.g., separate |
| Complaint Emails project). Each stays under the threshold. In-context |
| continues to work.                                                    |
+-----------------------------------------------------------------------+

3.4 File Ordering Strategy

Research (Stanford “Lost in the Middle” paper) shows LLMs attend best to
content at the beginning and end of context, with weaker attention in
the middle. Optimize by placing critical instruction files first and
reference examples last:

  ------------------------- ---------------------------------------------
  Position                  File

  System prompt (always     Golden prompt template + core instructions
  first)                    

  Files 1–2 (near top)      DO’s and DON’Ts + Tone guide (always
                            critical, always needed)

  File 3 (middle)           Best Lines & Phrases (reference material,
                            drawn from as needed)

  Files 4–13 (near end)     10 example emails (Claude matches the closest
                            to current task)
  ------------------------- ---------------------------------------------

File naming: Use clear, descriptive names.
“Example_Email_Cold_Outreach.txt” not “example1.txt”. Helps both Claude
and Patrick identify files during Friday updates.

6. Feedback System & Friday Review

6.1 Why Feedback Can’t Stay in Claude Conversations

Critical constraint: In shared Claude Projects, each member’s
conversations are private. Patrick cannot see staff conversations unless
they are manually shared one by one. This makes in-conversation feedback
invisible for Friday review.

Solution: Staff types feedback in the Claude conversation (Claude
responds “✅ Logged” per system prompt instruction, using ~2 tokens).
Then staff copies the same 1–2 line feedback to #ai-feedback Teams
channel. Claude searches this channel on Friday.

6.2 System Prompt Instruction for Minimal Token Usage

+-----------------------------------------------------------------------+
| ADD TO EVERY PROJECT’S CUSTOM INSTRUCTIONS                            |
|                                                                       |
| FEEDBACK HANDLING:                                                    |
|                                                                       |
| When the user’s message starts with “FEEDBACK:” or contains a rating  |
| like “3/4” or “4/4” at the end of a conversation after a task is      |
| complete:                                                             |
|                                                                       |
| • Respond ONLY with: “✅ Logged.”                                     |
|                                                                       |
| • Do NOT elaborate, ask follow-up questions, or summarize.            |
|                                                                       |
| • The feedback value is in the human’s words, not Claude’s response.  |
+-----------------------------------------------------------------------+

6.3 Friday Review Workflow (15 Minutes)

Who: Patrick. When: Friday afternoon. Where: New Claude conversation
(any project).

1.  Pull staff feedback (3 min): Ask Claude to search #ai-feedback Teams
    channel for this week’s messages. Group by task type, rating
    distribution, common issues.

2.  Pull client reply data (3 min): Ask Claude to search shared Outlook
    mailbox for client replies this week. Analyze: positive responses,
    follow-up questions (gaps in our emails), negative signals.

3.  Identify improvements (4 min): Ask Claude to cross-reference both
    datasets. Recommend top 3 prompt changes, new DO’s/DON’Ts, best
    lines to save.

4.  Update Project Knowledge (3 min): Patrick edits relevant files in
    claude.ai Project settings. Manual upload of updated files.

5.  Notify team (2 min): Quick message to #ai-feedback: “Week X updates:
    [what changed and why]. Try the updated email prompt.”

Flywheel: Staff feedback + client reply data → Prompt improvements →
Better outputs → Higher ratings + better client responses → More data →
Better prompts. Compounds weekly.

7.3 Seeding from 3-Year Email Archive

1.  Week 1: Ask Claude to search Outlook shared mailbox for the 20 most
    recent client proposal emails. Claude analyzes: best openers,
    strongest CTAs, most effective personalization, patterns in emails
    that led to bookings.

2.  Week 2: From Claude’s analysis, manually select the best emails as
    Project Knowledge example files. Populate Best_Lines.txt with
    extracted patterns. System is now seeded with 3 years of proven
    human intelligence.

3.  Week 3+: Flywheel takes over. Claude-generated 4/4-rated outputs
    gradually replace human examples. Best lines grow from weekly Friday
    reviews. System improves beyond the human baseline.

8. M365 Search Optimization [NEEDS RESEARCH]

This section contains our current best understanding but needs deeper
research. The attached handoff prompt asks the next Opus session to
research and fill these gaps.

8.1 What We Know

- Claude’s M365 connector provides read-only search access to Outlook,
  SharePoint, OneDrive, and Teams.

- Search is query-based: Claude sends a search query and receives
  relevant snippets/summaries, not full documents.

- Results are injected into the conversation context alongside Project
  Knowledge.

- Each user sees only what their M365 permissions allow.

- All team files must be in SharePoint/OneDrive (cloud-stored), not
  local desktops.

- Shared mailbox provides unified client email history regardless of
  which staff member sent/received.

8.2 What We Need to Know

- Search syntax: Does the connector support KQL (Keyword Query
  Language), natural language queries, or both? Can we use operators
  like “from:client@email.com” or “date:2025-01”?

- Result volume: How many results does a single search return? Top 5?
  Top 10? Can we control this?

- Token cost: How much context do returned search results consume? A
  5-result search might inject 2K tokens or 20K tokens — this matters
  for budget.

- Sequential searches: Can Claude do multiple M365 searches in one
  conversation? (e.g., first Outlook for emails, then Teams for phone
  notes, then SharePoint for past proposals)

- Filtering: Can we filter by mailbox, folder, date range, file type,
  Teams channel name?

- Shared mailbox: Does Claude auto-detect the shared mailbox, or must
  the golden prompt specify the mailbox address?

- Language: How does the connector handle Finnish-language email
  content? Does search work in Finnish? Does it handle mixed
  Finnish/English?

- Freshness: What is the indexing delay? Minutes? Hours? Does a
  just-received email show up immediately?
