## CONTEXT: The Existing System

A CEO (Patrick Heiskanen, 1658 Holdings Oy, 10-company portfolio) has built a manual workflow
for human-AI collaboration across 50+ sessions. The system runs in Claude Code (Sonnet 4.6).
Budget: zero additional tools unless clearly justified.

### What the system does TODAY (manually):

1. **CURRENT-STATUS.md** — session state file. Written at session END for next session START.
   Contains: Current State block, Rolling Window (last 5 sessions), Compressed History, Context Pack.
   The Context Pack compiles the most relevant patterns and knowledge for the NEXT session.
   Result: each session starts with ~10% context pre-loaded, not cold.

2. **Three-tier pattern system:**
   - Tier A: Always-loaded rules in CLAUDE.md (~15 battle-tested rules)
   - Tier B: `_shared/best-practices/` files — load on demand (15+ files, routed via _index.yaml)
   - Tier C: `_archive/` — superseded or low-use patterns
   - Promotion path: Tier B → Tier A after 3+ confirmed uses
   - Demotion path: no activations in 90 days → archive

3. **session-reasoning-harvest** (NEW, confidence 0.3, not yet validated):
   At session END, write 3-5 reasoning chains — the HOW/WHY behind AI decisions, not just WHAT.
   Example: "Why pgvector in Wave 1A: ALTER TABLE on 500+ live rows = expensive; 30-min addition
   now vs. painful migration later." These can be pre-loaded into future spawn prompts.
   Estimated value: 15-30 min saved per complex session once library has 20+ entries.

4. **pre-brief-reduces-corrections** (NEW, confidence 0.7, 1 confirmed use):
   Add 5-line company context card at session START before mining external sources.
   Prevents Claude defaulting to generic assumptions (e.g. "use Slack" when company is M365).
   3 corrections occurred in one session that a pre-brief would have prevented.
   Estimated gain: 2-3 fewer correction rounds = ~15-20 min saved per mining session.

5. **PreCompact hook** — fires before context compression, writes current state to BUILD-STATE.md.
   Prevents reasoning chain loss at 60% context.

6. **Warm packs** — pre-compiled topic-specific context bundles. On session start, the warm pack
   ID from the context pack tells Claude which ~50-line bundle to load. Replaces full codebase reads.

7. **Opus system reviews** — every 10 sessions, Opus audits: KB consultation rate, pattern harvest
   rate, contradiction scan, cross-pack propagation. Graduate criteria: KB consulted >40% +
   harvest >20% over 2 consecutive reviews.

### Current leverage metric (estimated session 64):
- Patrick input: ~30 min (paste source, 3 corrections, approve outputs)
- AI output equivalent: ~3-4h manual work
- Ratio: ~6-8x leverage
- Target: 12-15x (same safety, fewer correction rounds)

### The leverage leak identified:
The biggest single waste is **mid-session corrections** when AI defaults to generic assumptions
that contradict company context. Each correction = re-read + re-write + approval = ~5-7 min lost.
3 corrections/session × 5 min = 15 min of the 30-min human time is correction overhead.

## RESEARCH FINDINGS (from web search, 2026-03-12):

These tools/papers were found that may be relevant:

**A. DSPy + GEPA optimizer (Stanford, 2025)**
- Framework: treat prompts as code, not text strings
- GEPA: human provides TEXT feedback ("why did this miss?") → optimizer automatically rewrites
  prompts to prevent that class of mistake in future runs
- Example result: accuracy 46.2% → 64.0% in one optimization cycle
- Analogy to our system: each correction Patrick makes = GEPA training signal
- Source: https://dspy.ai/api/optimizers/GEPA/overview/

**B. Mem0 — production memory layer (2025)**
- Automatically extracts what's worth remembering from conversations
- Update phase: compares new info with existing memories, updates or deprecates
- Graph approach: memories with relationships, confidence scores, temporal decay
- Performance: 26% accuracy boost vs OpenAI built-in memory, 91% faster, ~2K tokens/query
- Analogy: automated version of our session-reasoning-harvest + context pack compilation
- Source: https://mem0.ai/research

**C. MemPO: Self-Memory Policy Optimization (Feb 2026, arxiv 2603.00680)**
- Agents learn to autonomously summarize and manage their OWN memory during a session
- Tokens belonging to memory get richer feedback signals → guide rollout process
- Results: +25.98% F1 over base model, -67.58% token usage
- Analogy: automated version of our /compact + reasoning-harvest combination
- Source: https://arxiv.org/abs/2603.00680

**D. MemRL: Self-Evolving Agents via Runtime RL on Episodic Memory (Jan 2026)**
- Agents improve their memory management via reinforcement learning at runtime
- Not just storage — agents learn WHEN and WHAT to remember based on task outcomes
- Source: https://arxiv.org/html/2601.03192v2

**E. Agentic AI Maturity Model L1-L4 (Dextralabs, 2025)**
- L1: Human reviews every output
- L2: Human reviews most outputs, AI handles simple tasks
- L3: Human reviews only exceptions and blockers
- L4: Human sets goals, AI handles full execution + escalates edge cases
- Patrick's current system: L2→L3 transition
- Source: https://dextralabs.com/blog/agentic-ai-maturity-model-2025/

- A: Top 2 quick wins, implementable in 30 days, no new tools

**Round 2:** Cross-challenge.
- A challenges B's top tool pick: is the setup cost worth it for a 1-person operation?

**Round 3:** Final verdict per persona.
Each gives: IMPLEMENT NOW / IMPLEMENT LATER / SKIP + one-line reason.
Cover: DSPy GEPA, Mem0, MemPO concepts, Maturity Model L3 target.
