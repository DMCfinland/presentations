Patrick correction (session 100): Benjamin built a compound leverage table (baseline_multiplier × ai_multiplier) to answer "is 200x plausible?" The table is arithmetically correct but the inputs (5x pre-AI elite, 10x AI multiplier) are qualitative claims, not measured quantities. The output looks like a result but is just false precision on unmeasured inputs.

**Why:** Using math to resolve a non-mathematical question creates the illusion of rigor. The arithmetic is sound but the framing is wrong. The right frame for "is 200x plausible?" is STRUCTURAL: "does this person's output compound across time, teams, and domains non-linearly?" — not a multiplication table.

**How to apply:**
- When a question is about magnitude/plausibility of a human capability claim, ask the structural question first (what mechanisms produce compounding?) before reaching for a sensitivity model.
- If you DO build a table on qualitative inputs, label it explicitly: "arithmetic model on qualitative inputs — not empirical." Never present it as the answer.
- The table is still useful for establishing boundary conditions (e.g., "100x requires BOTH 10x baseline AND 10x AI multiplier simultaneously") — just not as validation of the central claim.
